## 2026-09-16 — Decoupled regression baseline from EX-001

- **Explain it like I'm 10:** AIExpert's "did I still pass the test" check was pinned to one specific old test result that might one day not exist anymore. Gave it its own permanent notebook to compare against instead, so the check always has something real to measure itself against.
- Flagged directly by the user: `references/evaluation.md` hardcoded `exercises/EX-001-results.md` as "the prior baseline" for every future regression run, permanently. EX-001 is a specific, mutable, still-in-progress backlog item (Codex leg blocked) — not a fixed artifact — so this repeated the exact stale-pointer failure mode proposal 0001 already fixed once, and would break again the moment EX-001 is retired/renumbered/superseded, or on any fresh install where EX-001 never ran at all.
- Fix: added `references/regression-log.md` as a dated, append-only, exercise-independent record of every regression run. `evaluation.md` now points there instead of a named exercise. Seeded the workspace copy with the 2026-09-16 EX-001 baseline (5/5 pass, Claude leg only) as its first entry. The `ai-expert-kit/shared/references/` template copy ships both files with an empty log, since a fresh install has no baseline yet.
- No regression prompts have been re-run against the current instructions (including today's leverage-lens change) since this fix — that's the next open item, to become the log's second entry.

## 2026-09-16 — Added the playbook as the priority deliverable

- **Explain it like I'm 10:** AIExpert used to just keep a pile of research notes. Now it also keeps a separate "here's what you should actually do about it" list — real advice, not just raw facts you have to figure out the meaning of yourself.
- Requested directly by the user: raw ledger entries and dated findings weren't the useful output — they wanted synthesized, opinionated, actionable recommendations ("how to build a better mousetrap"), with the ledger's evidence as backing, not the deliverable itself.
- Added `knowledge/playbook.md`: opinionated recommendations with a Category, Confidence (`established` / `emerging` / `opinion`), Recommendation, Why, Evidence (links back to the ledger), Last updated, and Status (same supersede-don't-erase discipline as the ledger). Seeded with four entries synthesized from tonight's session: instructions aren't controls (regression-test every governing-instruction change), route cross-agent feedback through shared versioned artifacts not direct messaging, air-gap agents from each other's governing writes and shared coordination surfaces, and MCP-style tool binding as a converging-but-still-moving standard.
- Updated `.claude/agents/ai-expert.md` and `.agents/skills/ai-expert/SKILL.md` (synced to their `ai-expert-kit/` copies, plus an empty `playbook.md` template added to `ai-expert-kit/shared/knowledge/` for fresh installs): added a "Playbook" workflow step and made it explicit that a scan which only logs ledger entries without checking whether the playbook needs updating is incomplete. Added a `Playbook` line to the Output contract / Response shape, between Implication and Try it.
- Added a Playbook tab to the portal (`ai-expert-portal/`), as the first/lead tab ahead of Recommendations, per its new priority. Building it surfaced a real parser bug — the schema-documentation HTML comment in both `playbook.md` and `ledger.md` contains an example `## ` heading, which the naive section-splitter parsed as a spurious first entry. - `knowledge/index.md` (and its kit template copy) updated to list the playbook first under Files.

## 2026-09-16 — Added the ambiguous-retraction exception

- **Explain it like I'm 10:** AIExpert was told "something you wrote earlier was wrong" with no other details, and instead of asking "wrong how, and about what?", it guessed and started editing files on its own. Now it has to ask first when someone gives it a vague correction like that, instead of guessing.
- The regression suite was then run (5 prompts, second entry in `references/regression-log.md`). 4/5 matched the baseline exactly. Prompt 5 ("We now know an older ledger conclusion was wrong" — no specifics given) diverged: the baseline asked for the specific conclusion/correction and touched no files; this run instead independently researched, self-selected a candidate ledger entry, and edited three files (`ledger.md`, `index.md`, `backlog.md`) without confirming with the user first. The correction's content was evidence-checked and kept by user decision — this entry is about the *process* gap it exposed, not the content.
- User decision: keep the correction; close the gap by requiring approval going forward for this specific pattern.
- Fix: added an "ambiguous retraction exception" to both `.claude/agents/ai-expert.md` (Cumulative knowledge workflow + Improving AIExpert sections) and `.agents/skills/ai-expert/SKILL.md` (Core workflow + Self-improvement boundary sections), synced to their `ai-expert-kit/` copies. AIExpert must now ask which entry and what changed before editing, when the *user's own prompt* is the sole trigger for a claimed correction and gives no specifics. This is narrower than the existing "autonomous updates to ordinary research notes supported by evidence" allowance, which still applies unchanged when AIExpert itself surfaces a contradiction during its own scouting/research — only user-asserted-but-unspecified retractions now require asking first.
- Regression prompt 5 has not been re-run against this fix yet; recommend it becomes the third `regression-log.md` entry on the next Improve-mode pass, expecting it to now match the original EX-001 baseline (ask, no file edits) rather than the divergent run above.
